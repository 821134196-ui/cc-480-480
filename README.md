# 防火门闭门器巡检与复位系统

面向物业的防火门巡检、故障维修与复位管理演示系统。零第三方运行时依赖，仅使用 Node.js ≥ 22.5 内置的 `node:sqlite`、`node:http`。

## 一条命令启动

```bash
npm start                 # 首次启动自动建库并生成演示数据（楔门 / 联动失败 / 复位退回 / 临时封控 / 逾期）
npm start -- --reset      # 删除数据库并重新生成演示样例
PORT=8080 npm start       # 指定端口
```

启动后访问 http://localhost:3000

测试：

```bash
npm test                  # node:test，20 个用例
```

## 核心业务规则

1. **巡检**：按路线逐门检查门扇、门框、闭门速度、双扇顺序、电磁释放联动；现场无法进入单独留痕并自动生成重检提醒。
2. **故障上报**：同一门体同类未关闭故障不重复开单（工单唯一）；门体维修中/待复位时拒绝重复上报。
3. **维修占用**：数据库部分索引保证同一门体同时只有一张 `open/in_progress` 维修单。
4. **职责分离**：维修完工后门体进入「待复位」，必须由维修负责人之外的另一人执行复位测试；维修人测试自己的单直接拒绝。
5. **复位测试**：门扇、门框、闭门速度必检；双扇门加检顺序关闭；常开门加检电磁释放联动（可由模拟适配器自动采集）。所有适用项合格才关闭故障、恢复正常；任一不合格即「复位退回」，故障保持未关闭，可重新开维修单。
6. **同一故障不能重复关闭**：已合格关闭的故障不能再次提交复位。
7. **临时措施**：仅安全主管可批准，设到期时间；进程内调度器到点自动失效、门体回到待维修并留痕；复位合格时自动解除。
8. **停用/封堵**：有进行中维修单时不可停用；停用门体不参与巡检、不可上报，记录封堵情况。
9. **逾期**：维修单超时、巡检逾期自动统计；维修超时只留痕一次。

## 七类留痕事件

门体被楔开 `wedged`、闭门过快 `close_fast`、双扇顺序错误 `seq_error`、信号无回传 `no_signal`、现场无法进入 `inaccessible`、维修超时 `repair_overdue`、复位失败 `reset_fail`（另有临时措施批准/到期、停用/恢复等）。

## 页面

总览 · 防火分区图 · 路线巡检 · 门体部件 · 故障列表 · 维修进度 · 复位测试 · 逾期统计 · 门体详情。

- 分区图：2D 示意，分区矩形 + 门体短线与编号；常开防火门编号为耐火红；颜色/虚线区分状态。
- 闭门测试页：毫秒时间刻度显示启动/入锁/闭合过程，标注 <2s 过快区与 >5s 闭合困难；双扇 A/B 并列展示并给出顺序结论。
- 门体详情顶部：临时措施生效时持续显示橙红横幅与到期倒计时。
- 视觉：建筑白 `#f8f6f2`、耐火红 `#a83228`、石墨灰 `#3d3b37`；状态均配文字徽标，不单靠颜色。

## 存储与适配器

- SQLite 数据库：`data/app.db`（设备台账、工单、事件、提醒、联动故障脚本）。
- 门体照片：`data/photos/`，种子生成 SVG 占位图，详情页可上传实拍。
- 进程内调度器：扫描 `reminders` 表触发巡检/维修提醒、维修超时留痕、临时措施到期处理。
- 电磁释放模拟适配器：`src/adapter.js`，按门体编号的持久化脚本返回 `ok / no_feedback / no_release`；门体详情页「模拟释放联动」可注入/清除故障脚本，演练复位退回→维修→复测合格。
