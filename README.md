# 防火门闭门器巡检与复位系统

物业防火门巡检、故障维修与复位闭环管理：楼栋 / 防火分区 / 门体编号 / 常开常闭 /
闭门器 / 顺序器 / 电磁释放 / 封堵情况 / 巡检任务 / 故障维修 / 复位测试 / 停用标记。
设备数据为演示内容。

## 一条本地命令启动

```bash
bash run.sh
```

重建演示数据库（含楔门、联动失败、复位退回样例），启动进程内调度与 Web 服务：
<http://127.0.0.1:8066>

- 演示样例：FM-101 门体被楔开；FM-203 电磁释放联动失败、信号无回传；
  FM-102 维修后复位测试不合格被退回；FM-105 维修超时；FM-106 临时措施已到期。
- 可选环境变量：`PORT=9000 HOST=0.0.0.0 bash run.sh`

仅重建样例数据：`python3 -m firedoor.seed`
测试：`python3 -m unittest discover -s tests -v`

## 业务闭环与规则

1. 巡检员按路线逐扇检查门扇、门框、闭门速度（90°→全关合格区间 **3~10 秒**）、
   双扇顺序关闭、电磁释放联动；路线全部门检查完才能结束。
2. 发现故障：楔开、闭门过快、双扇顺序错误、信号无回传、现场无法进入、
   维修超时、复位失败分别建单并全程留痕；门体进入待维修。
3. 维修：六项必做步骤（现场警戒、拆检、维修更换、速度调校、联动恢复、自检）
   全部完成才能提交；同一门体同一时刻只允许一张活动维修单占用
   （数据库部分唯一索引 + 应用层双重保证）。
4. 复位：**必须由维修人以外的另一人执行**；门扇、门框、闭门速度、双扇顺序、
   联动、封堵全部合格才恢复正常；任一不合格退回维修并挂“复位失败”故障，
   调校/联动/自检步骤打回重做。
5. 同一故障只能关闭一次；同类型活动故障重复发现沿用原单，不重复建单。
6. 安全主管/经理可批准带期限的临时措施（门体详情顶部持续可见），
   到期自动失效并回到待维修；区域权限（`zone_scope`）约束所有门体操作。

## 结构

| 路径 | 说明 |
|---|---|
| `firedoor/db.py` | SQLite 表结构（设备/任务/工单/复位/措施/信号/提醒/事件留痕） |
| `firedoor/service.py` | 业务规则、状态机、模拟电磁释放适配器 |
| `firedoor/demo.py` | 演示设备台账与楔门/联动失败/复位退回/逾期样例 |
| `firedoor/scheduler.py` | 进程内守护线程：生成巡检任务、SLA 超时、措施到期、提醒 |
| `firedoor/server.py` | 标准库 HTTP 服务 + REST + 静态前端 |
| `firedoor/static/` | 单页前端（原生 JS，含分区图与闭门时间刻度图） |
| `data/firedoor.db` | SQLite 库（运行时生成） |
| `data/photos/` | 门体照片本地目录（含 FM-101 演示占位图） |
| `tests/test_firedoor.py` | 21 项规则测试 |
